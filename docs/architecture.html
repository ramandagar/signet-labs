01 — The problem & thesis

Self-reports are not evidence

Every autonomous agent in production makes claims: “tests passed”, “payment sent”, “identity verified.” The log line saying so is not evidence — it's a self-report. Pipelines go green over stale, incomplete, or fabricated work, and the failure surfaces downstream, where it's exponentially more expensive.

Proof-or-Stop is the admissibility layer: the runtime decides which agent claims a lifecycle may safely act on. Dapr 1.18 and Diagrid Catalyst prove what happened (infrastructure attestation). var-runtime decides whether what happened is admissible — fresh, bound, hash-intact, signature-valid, or the lifecycle stops with machine-readable recovery.

Validated shape: a gated unattended loop passed 10/10 scenarios with zero false-done outcomes; receipt bundles rejected 18 tamper classes with zero false accepts; gated loops cut visible-pass/hidden-fail from 31/1800 to 2/1800.

The gate's five mechanical checks

claim tests_passed @ commit_def456 ├─ present evidence artifact exists ├─ fresh age 12s ≤ max 300s ├─ bound commit_def456 == target ├─ hash intact sha256(payload) ✓ ├─ signed ci-key-1 (trust anchor) ✓ └─ positive tests: 214 passed, 0 failed → ADMIT lifecycle advances # any check fails: → HALT EVIDENCE_STALE (847s > 300s) recovery: re_run_tests

03 — The life of a claim

End to end, in eight steps

1

Session starts identity.py

Alice's identity is captured; a signed envelope (principal, agent, scoped permissions, expiry) is issued. Budget declared: $2.00 / 1800s.

2

Agent works runtime.call_tool

Every tool call is wrapped: envelope verified + permission checked → budget guard → envelope injected into MCP _meta → execution timed → SERF classifies failures → performance recorded → event attested → checkpoint.

3

The agent claims done gate_claim

{claim: "tests_passed", target: {commit_sha}, confidence} — the gate looks up the proof registry's evidence requirement.

4

Evidence is fetched & verified evidence.py

A registered fetcher (GitHub Actions API, CI webhook, approval log, hosted http_json) returns a signed artifact. Five mechanical checks run.

5

ADMIT or HALT GateDecision

ADMIT advances the lifecycle. HALT returns structured recovery (re_run_tests) — the agent self-corrects deterministically. Human-in-the-loop: deploy_to_production requires a senior-engineer approval, chained into the envelope.

6

Cost governance cost.py

Every LLM call metered (tokens/USD); stakes route models — irreversible work → flagship, reversible → fast; ≥80% budget → degrade; over → hard stop.

7

Crash → resume state.py

Process dies mid-PR. runtime.resume(session_id) reloads the last checkpoint: messages, tool results, meter totals, approvals. No re-execution, no re-payment.

8

Attestation & audit attestation.py

Every event hashed into a chain, batch signatures linked to the previous signature. Audit query: “every action on behalf of Alice.” Export bundle verifies offline.

The 8-step demo runs in ~2s

$ python3 demo.py
STEP 1  session s_5f2c91 · budget $2.00
STEP 3  tool calls — envelope verified, metered, attested
STEP 4  fresh → ADMIT · stale → HALT EVIDENCE_STALE
        wrong sha → HALT EVIDENCE_UNBOUND · re-run → ADMIT
STEP 6  crash → resumed at step 7 · meter intact
STEP 7  chain verified · 17 events · offline bundle ✓
STEP 8  deploy → HALT (no approval) → bob approves → ADMIT

HALT is a feature

Every HALT carries a machine-readable recovery instruction — the difference between an agent that retries blindly and one that deterministically self-corrects. 13 adversarial scenarios (stale, unbound, tampered payload, forged signature, negative result, wrong approver role, low confidence…) each produce exactly one correct verdict. evals/gate_evals.py

04 — AI & agent integration

How agents plug in

embedded (any framework)

Wrap tool calls

The runtime wraps plain callables — LangGraph nodes, CrewAI tools, OpenAI SDK function calls all route through call_tool. Identity injection, metering, SERF, attestation come free.

langgraph adapter

Gated nodes

gated_node(rt, session, "tests_passed", target_fn) wraps a graph node so its output must pass the gate before the graph advances — HALT raises GateHalted with structured recovery for a correction node. attach_checkpointer bridges durable state (lazy import).

var as MCP server

7 tools over stdio

Any MCP client (Claude Desktop, Cursor) gets var_start_session, var_gate_claim, var_submit_evidence, var_record_approval, var_session_usage, var_verify_session, var_audit_session. Identity envelopes ride tools/call _meta — the propagation primitive MCP itself lacks.

Five lines to first gated claim

rt = VerifiableRuntime(store="var.db", proofs="proofs.json")
s  = rt.start_session(principal_id="alice@co", permissions=["run:tests"],
                     budget=Budget(max_usd=2.00))
rt.call_tool(s, "run_tests", ci, permission="run:tests")  # wrapped: identity, meter, attest
d  = rt.gate_claim(s, {"claim": "tests_passed", "target": {"commit_sha": sha}})
# d.decision == "ADMIT" — or HALT with d.error.recovery

Where the "AI" is (and isn't)

The gate is not a model. Evidence verification is deterministic machinery — hashes, signatures, freshness arithmetic — so verdicts are replayable and identical every run. LLMs live where they belong: in the agent frameworks above the runtime, and in the agents' own judgment about what to claim. The runtime's only trust decision — admissibility — is mechanical by design. Stakes-based model routing (flagship vs fast) is the one place model choice is governed, and it's declarative policy.

No network calls, no clocks inside verification paths (GateEngine.now is injectable), no randomness — render/replay safe.

06 — Security model

Trust boundaries, mechanically enforced

What's verified, and how

pathmechanism
Identity envelopesJWT-shape, HMAC-SHA256, expiry checked every call; permissions scoped per tool
Evidence artifactscontent hash recompute + producer-key signature via trust-anchor registry
Execution historySHA-256 chain, batch signatures linked to predecessor; edit/delete names the exact broken entry
API keyssha256 at rest, constant-time compare, revocable, per-tenant
Stripe webhooksHMAC over t.payload, 5-min replay window, constant-time
Hosted evidence fetchhttps-only URL templates, 10s timeout, 502 on unreachable

Known ceiling (documented in code): HMAC is symmetric — swap TrustAnchor.sign/verify_sig for Ed25519 when third parties must verify without the signing key; envelope format is unchanged.

Tamper classes caught

  • stale evidence (age > max_age_seconds)
  • evidence bound to the wrong target (stale-checkout CI)
  • payload edited after signing (hash mismatch)
  • signature from an untrusted key
  • fresh, signed evidence of FAILURE
  • approval by the wrong role / below confidence floor
  • history row edited in the database (chain breaks at entry N)
  • history row deleted (downstream hash mismatch)
  • cross-tenant session access (403) · revoked/forged keys (401/403)
  • quota + rate abuse (402/429)

Every one of these has a test or eval case asserting the exact verdict.
