Six guarantees, one runtime

01 · EVIDENCE GATE

Proof-or-Stop

Claims like tests_passed or payment_sent are ADMITted only with evidence that is fresh, bound to the exact target, hash-intact, and signature-valid. Otherwise: HALT, with machine-readable recovery.

02 · IDENTITY BROKER

Signed identity, end to end

Every tool call carries a signed envelope — principal, agent, scoped permissions, approval chain, expiry — in the MCP _meta. Per-user authorization and auditing, finally standard.

03 · COST GOVERNOR

Agent economics

Token, USD, and wall-clock budgets per session. Stakes-based model routing: irreversible work earns the flagship model, reversible work goes cheap. Hard stop, degrade, or escalate.

04 · DURABLE STATE

Crash → resume

Checkpoints after every tool call and LLM response. A crashed session resumes at the exact step it died — state and meter intact. No re-execution, no re-payment.

05 · SERF

Errors machines can use

Every failure classified into a six-category taxonomy with a recovery strategy and backoff plan. Agents self-correct instead of parsing error strings.

06 · ATTESTATION

Tamper-evident history

Every event hashed into a chain with linked batch signatures. Edit one row in the database and verification names the exact broken entry. Auditors verify offline.

rt = VerifiableRuntime(store="var.db", proofs="proofs.json") s = rt.start_session(principal_id="alice@co", permissions=["run:tests"], budget=Budget(max_usd=2.00)) rt.call_tool(s, "run_tests", ci, permission="run:tests") # identity-injected, metered, attested d = rt.gate_claim(s, {"claim": "tests_passed", "target": {"commit_sha": sha}}) # d.decision == "ADMIT" — or HALT with d.error.recovery telling the agent what to do next
